Relazione Tecnica: Gaming Vault

Realizzazione del Progetto d'Esame "Capolavoro" - Matteo Paraschiv

1. Obiettivo del Progetto

Il progetto Gaming Vault è un'applicazione web Full-Stack progettata per la gestione di una libreria videoludica personale. L'obiettivo è dimostrare la capacità di integrare diverse tecnologie informatiche (Database, Backend e API esterne) in un'unica interfaccia coerente e reattiva.

2. Struttura del Progetto

L'applicazione è organizzata in modo modulare separando la logica di connessione, il backend e le risorse frontend:

gaming-vault/
├── db.php             # Connessione al database tramite PDO
├── index_gaming.php   # Pagina principale (Interfaccia, Form e Logica PHP)
├── relazione.html     # Questa documentazione tecnica
└── README.md          # Introduzione al repository GitHub

3. Architettura Dati (MySQL & PDO)

La persistenza dei dati è affidata a un database relazionale MySQL. La connessione avviene tramite il file db.php utilizzando l'estensione PDO.

Schema Relazionale (DDL):

CREATE TABLE generi (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(50) NOT NULL
);

CREATE TABLE giochi (
    id INT AUTO_INCREMENT PRIMARY KEY,
    titolo VARCHAR(100) NOT NULL,
    id_genere INT,
    FOREIGN KEY (id_genere) REFERENCES generi(id)
);

Punti chiave:

  • Sicurezza: Uso di PDO::ERRMODE_EXCEPTION per la gestione robusta degli errori e il debugging.
  • Integrità: Implementazione di una LEFT JOIN SQL in fase di lettura per relazionare la tabella dei giochi con quella dei generi, garantendo la visualizzazione dei nomi testuali invece dei semplici ID numerici.

4. Logica Server-Side (PHP)

Il file index_gaming.php gestisce le richieste HTTP tramite il metodo POST per l'inserimento sicuro dei dati nel database.

// Esempio di Prepared Statement contro SQL Injection
$sql = "INSERT INTO giochi (titolo, id_genere) VALUES (:titolo, :genere)";
$stmt = $pdo->prepare($sql);
$stmt->execute(['titolo' => $titolo, 'genere' => $genere]);

Questa sezione è fondamentale per la sicurezza informatica: i Prepared Statements sanitizzano l'input dell'utente, rendendo l'applicazione del tutto immune agli attacchi di tipo SQL Injection.

5. Arricchimento Dati via API (JavaScript Asincrono)

Una delle caratteristiche avanzate del progetto è l'integrazione asincrona in tempo reale con l'API REST pubblica di CheapShark.

// Esempio di chiamata asincrona con Fetch API
fetch(`https://www.cheapshark.com/api/1.0/games?title=${encodeURIComponent(titolo)}`)
    .then(response => response.json())
    .then(data => {
        if(data.length > 0) {
            document.getElementById(`img-${id}`).src = data[0].thumb;
        } else {
            document.getElementById(`img-${id}`).src = 'placeholder.png';
        }
    });
  • Fetch API: JavaScript interroga un server esterno per recuperare l'URL della copertina del gioco in tempo reale basandosi sul titolo inserito.
  • Manipolazione DOM: Le immagini vengono iniettate dinamicamente nella tabella senza ricaricare la pagina (approccio AJAX / SPA).
  • UX: È stato implementato un sistema di "fallback" che mostra un'immagine segnaposto di default se l'API non restituisce risultati.

6. Frontend & UX (CSS3 Moderno)

L'interfaccia segue una declinazione scura del Material Design in versione Gaming/Cyberpunk:

  • Uso di object-fit: cover per mantenere le proporzioni corrette delle copertine dei giochi nella tabella, evitando distorsioni.
  • Transizioni fluide ed effetti :hover per rendere i pulsanti e le card interattivi e responsivi al passaggio del mouse.
  • Layout responsive basato su elementi flessibili per garantire la massima leggibilità sia su desktop che su dispositivi mobile.
